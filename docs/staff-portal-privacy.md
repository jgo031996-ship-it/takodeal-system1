# Staff portal

The portal uses the shared cream and evergreen TAKODEÁL theme. Staff retain their photo and can open their profile from the header. Clock includes monthly attendance records, overnight punches, hours, missing punches, recorded lateness, and HQ exemptions. Refresh fetches current data; switching months reuses the last minute of attendance data.

Pay starts locked on every page load. Staff create a separate 6–8 digit Payslip PIN after verifying their staff login PIN. Changing it requires the current Payslip PIN. A salted PBKDF2-SHA256 verifier (300,000 iterations) is stored in the staff profile; the new PIN is never stored as plaintext. Five failed attempts trigger a one-minute local cooldown. Unlock state stays in memory and is cleared when leaving Pay, opening Profile, hiding the page, signing out, or after two idle minutes. Relocking clears rendered pay and cancels stale rendering and exports. Payroll collections are queried by the staff name/known nickname instead of loading every employee's records.

This is a screen privacy lock for the existing PIN-based Staff portal. It is **not Firebase authentication or database authorization**. The existing database rules allow public reads/updates to staff and payroll collections. A determined caller can bypass the UI and local cooldown, read or replace verifiers, or read payroll directly. Production access control needs authenticated staff identities and restricted rules/endpoints across Manager, Cashier and Staff together. This release does not pretend to solve that wider migration or silently change rules that the existing apps depend on. PINs should not be reused for other accounts. Forgotten vault PINs require HQ review; there is no unauthenticated self-reset bypass.

The install manifest now references actual square PNGs at 192 and 512 pixels, including a separately padded maskable version. Existing logo artwork is preserved. Apple touch icons use the 192-pixel icon. The app registers a versioned service worker and caches same-origin shell files; payroll/network API responses are not added to that shell cache. Device registration still needs HQ approval and PIN verification still needs connectivity. An already-installed OS shortcut may retain its old icon until its app metadata updates or it is reinstalled.

Validation uses isolated sample data and 13 Staff-specific tests alongside the existing system suite. No real staff PINs, attendance punches, device approvals, signatures or payouts were created during verification.
